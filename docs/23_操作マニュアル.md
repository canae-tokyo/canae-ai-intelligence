# CANAE AI Intelligence 操作マニュアル

## 1. 公開サイトを見る

次へアクセスします。

```text
https://canae-ai-intelligence.canae-tokyo.workers.dev
```

公開画面では、ダッシュボード、ニュース、6ジャンル、ランキング、相関図を確認できます。

## 2. 内部レビュー画面へ入る

次へアクセスします。

```text
https://canae-ai-intelligence.canae-tokyo.workers.dev/internal/review-candidates
```

1. Cloudflare Accessのログイン画面を開く
2. `canae.tokyo@gmail.com`で認証する
3. Review UIが表示されることを確認する

ログインできない場合は、別のGoogleアカウントになっていないか確認します。

## 3. 候補を確認する

Review UIでは次を確認します。

- タイトル
- 公式source URL
- 公開日
- 候補タイプ
- 重複判定
- 差分内容
- proposed record
- レビュー履歴

公式一次情報と一致しない候補は承認しません。

## 4. レビュー判断

候補詳細で担当者名と確認理由を入力し、次から選択します。

| 操作 | 意味 |
| --- | --- |
| 承認 | 正本データへの昇格候補として認める |
| 却下 | 不正確、不要、重複などの理由で使用しない |
| 保留 | 追加確認が必要 |

承認後も、すぐに公開されるわけではありません。

## 5. Promotion PRを作成する

承認済みで、必要項目が揃っている候補だけがPromotion対象になります。

1. Promotion対象候補を選択
2. 「Promotion planを生成」を押す
3. 対象ファイルと変更内容を確認
4. 「GitHub PRを作成」を押す
5. 作成されたPRのURLを開く

この操作はGitHub PRを作成するだけです。mainへ直接反映されません。

## 6. GitHub PRを確認する

PRでは次を確認します。

- 公式情報と内容が一致する
- 変更対象ファイルが適切
- ID重複なし
- URL重複なし
- `verified`条件が正しい
- secretや内部情報が含まれない
- GitHub ActionsがPASS
- Cloudflare Workers BuildがPASS

問題がなければSquash Mergeします。

## 7. 本番反映を確認する

merge後、CloudflareのProductionデプロイ完了を確認します。

次を開きます。

```text
/
/news
/genre/coding
```

確認項目：

- HTTP 200
- 追加データが表示される
- レイアウト崩れなし
- モバイル横スクロールなし
- 外部source URLが開く
- 通常404が正常
- 内部画面のAccess保護が維持される

## 8. ニュースの日常更新

通常運用は次の流れです。

```text
公式ニュース確認
  -> 候補登録
  -> Review UIで承認
  -> Promotion PR
  -> CI確認
  -> Squash Merge
  -> 本番表示確認
```

ニュースの事実部分とCANAE影響メモを混同しないでください。

## 9. データを直接修正する場合

直接JSONを修正する場合も、必ず作業branchとPRを使用します。

対象例：

```text
C-Ai-Map/data/news.json
C-Ai-Map/data/tools.json
C-Ai-Map/data/benchmarks.json
C-Ai-Map/data/canae-evaluations.json
```

mainへ直接commitしません。

修正後は最低限、次を実行します。

```bash
npm run validate:data
npm run validate:collection
npm run build
npm run lint
git diff --check
```

## 10. 検索公開を確認する

次を確認します。

```text
/robots.txt
/sitemap.xml
```

公開ページ：

- `index, follow`
- `X-Robots-Tag: noindex`なし
- canonicalが正式URL

内部ページ：

- Cloudflare Access必須
- `noindex, nofollow`

## 11. Search Console確認

Google Search Consoleへ`canae.tokyo@gmail.com`でログインします。

Property：

```text
https://canae-ai-intelligence.canae-tokyo.workers.dev/
```

定期的に確認する項目：

- Page indexing
- Sitemaps
- URL Inspection
- Crawl stats
- Core Web Vitals
- Security issues
- Manual actions

インデックス反映には数日から数週間かかる場合があります。

## 12. 問題が起きた場合

### 公開ページが表示されない

- GitHub Actionsを確認
- Cloudflare Workers Buildを確認
- Production Versionを確認
- 直前のPR差分を確認

### 内部画面へ入れない

- `canae.tokyo@gmail.com`でログインしているか確認
- Cloudflare Accessセッションを確認
- 別ブラウザまたはシークレットウィンドウで確認

### Promotion PRが作成されない

- 候補が`approved / accepted`か確認
- proposed recordの不足項目を確認
- GitHub Promotion secret設定を確認
- store hash競合を確認
- GitHub APIエラーを確認

### draftが公開された

重大な問題です。

- 新規mergeを停止
- 公開セレクタがVerified限定か確認
- 修正PRを作成
- 本番再デプロイ
- 正本文書とCHANGELOGへ記録

## 13. 禁止事項

- Production URLを勝手に変更しない
- Cloudflare所有アカウントを変更しない
- mainへ直接commitしない
- mainを自動mergeしない
- GitHub tokenやJWTを文書・PR・ログへ貼らない
- 未確認データを`verified`にしない
- 公開ベンチマークとCANAE評価を混同しない
- `/internal/*`のAccessやnoindexを解除しない
